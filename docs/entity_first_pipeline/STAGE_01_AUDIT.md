# Stage 1：先验证代码与冻结网格，再接入完整流程

本分支从 `d9900359d935538030f73ec0ab1d0e46d742ee4e` 独立创建，不修改 `main`，也不引用 PR18 之后的实验分支。当前阶段不运行语言模型、不运行 PSO、不重新求解，只完成两件事：第一，给网格拓扑、实体面积、孔洞面积和单元质量建立求解前硬门；第二，用冻结的 GitHub Actions Run `30576340910` 原始 NPZ 验证现有 V4 最优网格会被硬门拒绝。

## Stage 1 通过条件

1. 审计脚本自身必须先通过确定性自测：完整矩形通过、内部删单元形成的假孔失败、孔洞尺寸漂移失败、细长三角形失败。
2. 冻结支座、单孔和三孔网格必须逐个读取 `region_pso_1.json → best.raw_file`，禁止读取论文截图、重画示意图或重新运行优化器。
3. 审计报告必须记录边界环数量、边界环面积、开放边界节点、网格面积、实体面积误差、最小角和最大半径比。
4. 当前冻结 V4 产物应被拒绝；若审计错误地接受全部产物，Stage 1 工作流失败。

## Stage 2 进入条件

Stage 1 的审计代码和冻结证据均完成后，才实现 `自然语言/点击 → IMP/ModelSpec → Gmsh OpenCASCADE 实体 → Physical Groups → Gmsh 网格`。这一阶段仍禁用 PSO，并要求同一 ModelSpec 在不同网格尺寸下保持实体面积、孔数、孔径、边界组和材料域完全不变。

## Stage 3 进入条件

固定实体与 Physical Groups 的测试全部通过后，才生成 CalculiX `.inp`，执行 `ccx` 烟雾测试，并核对节点集、单元集、材料、边界条件、载荷、求解状态和结果解析。

## Stage 4 进入条件

只有 Gmsh 与 CalculiX 的确定性全链测试通过，才重新接入区域尺寸场与 PSO；粒子只能改变 Gmsh Mesh Field 参数，不能创建、删除或修改实体、孔洞、边界环、材料域或 Physical Groups。
