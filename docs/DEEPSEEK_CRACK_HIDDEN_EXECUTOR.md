# DeepSeek 裂纹开放发现：隐藏执行器实验

## 隔离边界

本实验位于独立分支 `exp/deepseek-crack-hidden-executor`，堆叠在 `exp/deepseek-crack-open-discovery` 之上。它只新增 `experiments/hidden_executor/`、一个新运行脚本、一个新测试文件、一个新工作流和本说明文件，不修改原论文脚本、原 Skill 合同、原 MD、原工作流或既有结果目录。

## 两阶段合同

第一阶段只向 DeepSeek 提供用户问题、模型事实、已有数值证据、前轮公开提案及公开物理反馈。模型看不到工具目录、函数名称、参数合同、内部映射规则和执行器能力。它必须先提出至少两个竞争假设，并用工程语言冻结唯一下一步实验，包括实验目的、准备改变的量、保持不变的量、测量输出、判断规则和停止条件。

提案先写入 `proposal.json`，再生成 `proposal_seal.json`。封条包含提案 SHA256、前一轮链哈希、当前链哈希和 UTC 时间。隐藏映射与执行开始前会重新计算提案哈希；任何改写都会终止运行。

第二阶段由确定性隐藏执行器读取冻结提案。执行器只允许忠实映射当前后端能够实现的实验，无法映射时返回 `unsupported`，不会替换实验目的或补写预设路线。执行器的内部操作和原始结果保存于 `mapping_receipt.json` 与 `execution_audit.json`，不会回传给 DeepSeek。下一轮模型只能看到 `public_feedback.json`，其中仅包含实际物理改变、实际参数、数值观测、参数修复和限制。

## 允许复用的既有代码

新执行器以只读方式动态加载 `scripts/run_deepseek_crack_open_discovery.py` 中的真实有限元求解函数和缓存。它不更新该文件，也不向模型暴露其中的工具目录。裂纹微增量若不与结构网格节点对齐，执行器会吸附到完整网格步长，并同时记录模型请求值和实际使用值。

## 防泄露与防污染测试

静态合同检查包括：模型可见提示中不得出现任何内部工具名；提案必须先冻结再映射；映射前后提案哈希必须一致；无法映射的实验必须诚实拒绝；公开反馈不得包含内部操作名称；新运行器不得写入旧论文或旧实验结果目录。

## GitHub Actions

PR 事件只运行编译和静态合同测试，不读取 DeepSeek Secret。真实模型循环只在该隔离分支的 push 或手动触发中运行，并使用既有 `ds` Environment。所有冻结提案、哈希链、内部映射收据、真实数值结果、公开反馈和日志仅上传为独立 Artifact `deepseek-crack-hidden-executor`。
