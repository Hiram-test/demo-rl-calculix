# V4 工程智能与 Skill 设计原则

1. **工程智能的对象必须来自当前问题。** 几何、材料、荷载、约束、接触、缺陷和评价目标必须从当前用户文件、当前用户描述或当前任务解析结果中获得；缺失时询问用户，不得从旧版本、聊天上下文、旧 artifact、示例代码或默认常量中补入。

2. **Skill 代表一种工程经验的流程与规则库。** 每个 Skill 描述某一类工程方法，例如载荷与边界诊断、奇异性分析、弹塑性分析、网格优化、PSO、结果验证和模型修订。Skill 可以提供方法、步骤、物理原则、接口、示例和错误处理，但不得预置当前对象、当前几何、当前材料、当前参数、当前区域或当前答案。

3. **具体对象、参数与代码由 DeepSeek 针对当前任务生成。** DeepSeek 应先解析当前问题形成结构化 JSON，再选择适用的工程 Skill，并为当前模型生成或修改建模代码、CalculiX 输入、网格代码、求解脚本、后处理代码和优化代码。Skill 不是预写好的案例专用执行函数，也不是让模型只选择按钮和回填参数。

4. **禁止任何隐藏硬编码。** 禁止预置诸如长度、厚度、孔径、裂纹长度、材料参数、载荷值、承压宽度、区域坐标、网格等级、PSO 搜索范围等当前任务数据。唯一允许的固定内容是通用算法、文件格式、求解器接口、物理规则和工程方法。

5. **缺少必要信息时必须显式询问。** 不得静默猜测或使用默认值。若允许进行假设研究，必须明确标记为 AI 假设，说明依据和影响范围，并与用户提供或文件解析得到的事实分开记录。

6. **流程可以预先存在，路线不能预先写死。** “提出假设—选择证据—生成代码—执行—读取结果—修正—再执行”可以是通用循环；具体选择哪种问题类型、调用哪个 Skill、生成什么代码、使用什么参数、何时转向另一假设，必须由当前证据驱动。

7. **所有来源必须可追溯。** 每个关键参数必须记录来源：用户提供、文件解析、DeepSeek 推导、用户确认假设或算法配置。没有来源的值不得冒充工程事实。

8. **当前阶段不设置任何门禁。** 所有错误、异常、未通过项和中间结果只记录，不阻断计算、代码修改、重试、报告或论文生成。
