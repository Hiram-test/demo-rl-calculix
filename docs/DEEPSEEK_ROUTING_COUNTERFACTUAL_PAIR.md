# DeepSeek 路由独立反事实双样本

## 目的

本实验独立于既有论文主流程和多轮开放发现 runner，只检验一个问题：DeepSeek 的首轮路线分类究竟依据可核验的几何、拓扑与网格证据，还是被用户问题中的“裂纹”词面牵引。

它不是训练、DQN、优化或工具循环，也不会把模型回答再次送回模型。

## 反事实构造

两个匿名样本使用完全相同的 system prompt、路线目录、工具目录和输出 schema，仅替换个案证据包。

| 匿名样本 | 用户词面 | 模型事实 | 事后期望路线 |
|---|---|---|---|
| `specimen_2718` | 明确出现“裂纹” | 闭合矩形内边界、边界链连续、节点共享、没有相对自由面、没有连接中断 | 连续体局部几何评价 `R1` |
| `specimen_3141` | 不出现“裂纹”“断裂”等目标词 | 两条重合相对自由边界、节点不共享、跨面连接中断、零半径端点 | 内部拓扑不连续端点评价 `R2` |

期望路线映射只在两次回答都冻结后由 Python 评分器读取，不进入任何 DeepSeek message。

## 真实求解证据

发送给模型的网格历史来自仓库现有确定性 Python 有限元场景：

- 连续几何样本执行三档零圆角矩形开孔求解，暴露局部峰值、固定 15 mm 响应、远场位移、远场应力、应变能和平衡误差。
- 内部不连续样本执行三档双自由面模型求解，只暴露局部峰值、应变能和平衡误差。
- 既有 `diagnostic`、`skill_trace`、场景名称、圆角对照结论以及 `G_numeric`、`K_from_G` 等派生答案字段不会发送给 DeepSeek。

因此，本实验确实执行求解，但模型看到的是原始数值与拓扑事实，而不是仓库已有结论。

## 调用与缓存约束

- 整个运行只创建一个 API client。
- 两个匿名样本各调用一次 DeepSeek，总计严格两次。
- `max_retries=0`，非法 JSON、缓存未命中或分类错误均不触发修复调用。
- 两次请求的前两条 messages 逐字节相同；每例自己的第三条 message 才包含匿名证据包。
- 第一例回答不加入第二例 messages，避免跨样本污染。
- 公共前缀 SHA-256、原始 usage、缓存命中与未命中 token 均写入结果。

## 触发与产物

独立工作流只监听 PR17 实验分支首次新增的 `experiments/triggers/DEEPSEEK_ROUTING_COUNTERFACTUAL_PAIR_ONCE.md`。这是一次性 push 标记：本次提交会直接触发实验，后续脚本、文档或结果变化都不匹配该路径；工作流也不提供 `workflow_dispatch`，GitHub UI rerun 会由 `github.run_attempt == 1` 作业条件拦截。

工作流权限为 `contents: read`，结果只上传 GitHub Actions artifact，不回写分支，因此不存在结果提交再次触发模型调用的循环。

artifact 包含：

- 模型实际看到的公共 messages 与两个盲化证据包；
- 两次原始公开回答、模型名、结束原因和 usage；
- 逐例事后评分；
- 两例路线是否不同及主反事实指标是否通过；
- 实际请求数、客户端创建数、SDK 重试设置与缓存命中率。

## 判定

主指标只要求：

1. `specimen_2718` 选择 `R1`；
2. `specimen_3141` 选择 `R2`；
3. 两个路线不同。

工具适配、是否同时引用 `local_topology` 与 `mesh_history`、JSON 结构是否有效分别报告，不作为运行时门禁，也不会触发第二轮。
