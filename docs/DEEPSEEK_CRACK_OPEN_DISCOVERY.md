# DeepSeek 裂纹开放发现实验

## 目的

这个实验只回答一个问题：在没有场景专用必选 Skill、没有预设路线和没有结果导向完成门的条件下，DeepSeek 能否根据用户问题与逐轮有限元证据，自行决定是否继续加密、改变评价量、补充计算、请求缺失信息或停止。

原有论文流程和验证合同保持不动，本实验位于独立分支 `exp/deepseek-crack-open-discovery`，不替换任何既有结果。

## 允许提供给模型的知识

模型可以获得工程师应具备的高层工作原则：先固定工程决策与评价位置；区分直接观测、物理解释和未知；警惕点值、尖角、裂尖、点载荷和约束处可能出现的非收敛量；同时检查位移、能量、平衡、路径量、区域平均量及材料模型适用性；优先选择能够区分竞争假设的最小下一步计算；证据不足时可以请求信息或保留结论。

这些原则属于通用工程能力，不规定裂纹场景必须采用哪一种断裂参数、材料模型或 Skill 顺序。

## 禁止写入运行时提示的内容

运行时提示不得列出任何场景专用完成要求，不得出现“必须调用某 Skill”“必须先计算某量再计算某量”“只有走到某结论才能结束”等约束，不得把事后评分规则暴露给模型，也不得把原论文的裂纹路线作为示例答案。

## 开放工具目录

模型获得多个可选动作，包括继续同类加密、在固定物理距离取样、比较区域或路径量、进行小幅几何扰动后的能量比较、进行理论交叉检查、请求材料数据、请求边界或载荷信息以及直接停止并形成暂定结论。工具目录代表工程师可用的工作台，工具的存在不构成必选路线。

## 决策循环

每一轮只向模型提供用户原问题、当前模型事实、已经获得的数值证据、此前动作及其返回结果、剩余计算预算和完整工具说明。模型必须输出竞争假设、当前证据判断、一个下一步动作及简短工程理由。执行层只验证 JSON 结构、参数范围和预算，不检查动作是否符合预设路线。

## 终止规则

模型可以在任意一轮停止。系统只在预算耗尽、JSON 连续无效或求解器不可恢复失败时强制终止，不会因为某个指定 Skill 尚未出现而继续驱动模型。

## 事后盲评

运行完成后，独立评分器只读取已冻结的轨迹，评价模型是否围绕用户工程决策组织证据、是否识别了不适合继续追逐的量、是否选择了有区分力的下一步计算、是否控制变量、是否引用真实证据以及是否诚实保留不确定性。评分器不参与运行时决策，评分项中不要求出现任何固定 Skill 名称。

## 对照设计

同一个裂纹证据包支持两个入口：`guided` 使用上述工程师高层指南，`bare` 只获得通用科学分析要求。两组拥有相同工具、相同有限元证据、相同预算和相同模型参数，用于区分“工程知识框架的帮助”与“预设路线的暗示”。

## 成功证据

一次运行只能形成演示证据。正式结论至少需要多个随机种子、提示顺序扰动、工具名称盲化和反事实场景；例如把裂尖峰值递增但能量不稳定、或峰值与固定距离量同时稳定的证据包交给模型，检查它是否仍机械地复述同一路线。
