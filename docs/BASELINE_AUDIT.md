# 旧实现审计：四个对比算法的部署问题清单

- **日期**：2026-08-28
- **审计对象**：本仓库历史分支（`feat/amr-plan-run-20260826`、`exp/cross-passage-torsion-five-methods` 等）与其引用的 T 梁战役产物
- **结论**：用户的判断成立——四个对比算法的历史部署全部存在对象级错误，其中 Dörfler 的表现"甚至比均匀还差"可在留档数据中直接复核；根因是**自制网格实现替代了 Gmsh 重网格**。本仓库新框架（`visionamr/`）逐条修复，修复验证见验收门 G1（`scripts/run_smoke.py`）。

---

## 1. Dörfler：两代错误部署

**错误 1（更早）：整站切开冒充 Dörfler。** 旧代码 `run_element_doerfler` 逐单元算 η² 后，把含被标单元的整段跨向站二等分（`split_x_stations`）。加密对象从"单元 K"变成"跨向站"，一次把自由度整板堆到固端，两三轮尖端位移就贴上参考——制造了"三次就收敛"的假象。Dörfler 1996 的加密原子是被标单元本身，任何聚合后再切的实现都不是该论文。

**错误 2（后一代）：手写悬挂 8 切 + 冻结截面拓扑。** 8 月 26 日战役改为逐单元悬挂 8 切（自制 `refine_marked_hexes` + 1-irregular + `*EQUATION`），但 T 梁截面拓扑冻结（腹板 2×5、外挑 4、翼缘厚 2），逐单元 8 切只能把自由度花进截面与悬挂约束，无法表达尖端位移 QoI 需要的跨向分辨率。留档数据（`step8/G01_zz.json` 与评审 `artifacts/amr-plan-reviews/dorfler-review/REVIEW.md`）：

| N（方程数） | 悬挂 ZZ-Dörfler e_u | 均匀梯子 e_u | 差距 |
|---:|---:|---:|---:|
| ≈3200 | 0.155 | 0.096 (N=3456) | 1.6× |
| ≈4500 | 0.137 | 0.055 (N=4608) | 2.5× |
| ≈7000 | 0.114 | 0.022 (N=6912) | **5×** |
| ≈17000 | 0.061 | 0.041（全 8 切） | 1.5× |

另伴随固端反力诊断失败（cycle≥1 `rf_balance_ok=false`，RF 合力冲到 1.0–1.5 万 N，外荷载 5000 N）。这不是 Dörfler 定理被推翻，是**网格实现绑架了方法**：手写悬挂网格 + 错误的自由度去向。

**修复**：`visionamr/baselines/dorfler.py`——对象回到单元；标记是最小基数 bulk 集（单测锁定）；加密 = 被标单元局部尺寸减半 + Lipschitz 平滑 + **Gmsh 整体重网格**；停算只留空标记/预算帽/12 轮硬帽。修复后 L 形支架上 Dörfler 在匹配 N 处全程优于均匀（N≈12000 时 0.034 vs 0.093，约 3 倍），门 G1 自动判定通过。

## 2. 局部预测：硬编码六区背包冒充论文算法

旧实现是 2026-08-15 技术基线：X0–X5 六个硬编码跨向区段 × 三级 h × 固定 DOF 带背包（`src/local_prediction/geometry.py` 的 `PATCHES` 等），另有空 C3D20 局部问题（补丁上自由度为零仍画图）、CalculiX 拒绝的 C3D27 卡片、以及被 3×|T0| 发明规则在 n=1 停掉的外循环。这些都不是任何论文的算法。

**修复**：`visionamr/baselines/local_prediction.py`——按 ZZ 1987 自适应重网格程序 + Li–Bettess 1995 最优准则部署：逐单元 η → 误差均衡出逐单元目标尺寸（允许一步跨多级，单轮比值裁剪 [1/6,3]）→ Gmsh 重网格，probe+2 轮/预算档。其固有弱点（等分布不建模过渡带 → 预算超支 40%+）如实入指标，不做美化。Houston–Wihler 2016 的局部问题变体列为阶段二，不再冒名。

## 3. 强化学习：目标错配与状态缺失（V1 归档代码）

归档 `archived-src` 的 V1 DQN 存在：策略选全局 (cell,action) 但 Bellman 目标只在同 cell 上取 max（目标错配）；网格尺寸状态不进 Q 网络；全局状态恒为 [1,0]；无效重复动作不掩蔽（V2 文档 `STATE_AWARE_V2.md` 已自我记录这些问题）。另外图节点是 Abaqus 几何 cell，加密不改变拓扑，状态无法感知变化。

**修复**：`visionamr/baselines/rl_dqn.py`——图节点改为**区域**（与 VLA 对象对齐，用户设定）；特征含尺寸、误差/资源份额、预算进度；Double DQN 目标在全动作集上取 argmax；奖励不用参考解（无 oracle）；stop 奖励按预算利用率计，杜绝提前停止刷分；训练/部署求解分开记账。

## 4. 监督学习：此前无部署

历史分支没有可用的监督基线（无专家网格来源）。**新增**：`visionamr/baselines/supervised.py`——用修复后的 Dörfler 循环在训练实例上自造专家尺寸场（用户方案：拿规则/经典算法造专家库），MLP 回归节点尺寸场，部署时一个预算标量按探针网格实测校准（MeshingNet/AMBER 式），2 次求解。

## 5. 共同根因：没有用 Gmsh

旧战役全链条使用自制结构化六面体生成器（`tbeam_solid_hex.py` 等）与手写悬挂加密。后果：(i) 冻结拓扑使方法间比较失真；(ii) 悬挂约束引入反力诊断异常；(iii) "改尺寸"无法真正传导为网格变化。归档 `calculix_backend.py` 虽然调用过 Gmsh，但只用每虚拟 cell 一个 Box 尺寸场的固定模板。

**修复（框架级约定）**：`visionamr/` 中一切网格由 `mesher.generate_mesh`（Gmsh Python API + 尺寸回调）生成；方法只产出尺寸场（逐单元图或区域尺寸）；仓库不存在任何手写节点/单元操作（验收门 G2）。"让 Gmsh 直接改变一个区域的尺寸"由 `sizefield.RegionSizeField` 实现：`size(x)=min(h_bg, min_i(h_i+g·dist(x,region_i)))`。

## 6. 视觉侧历史问题

8 月 26 日战役的视觉分区三次求解中 rev1 与 PSO 认证的方程数撞车（均为 6048），实际只有两个不同网格；且 PSO 代理以实测平均尺寸锚定、解码却用名义尺寸，母粒子不自洽。**修复**：`visionamr/vla/`——三 N 互异是显式门（G4）；代理锚定名义尺寸，母粒子 (0,0) 严格复现 solve 2；PSO 加闭式种子（预算尺度/精度尺度）避免小种群早收敛；预算合规性成为一等指标（试点认证步同时降误差与降资源）。
