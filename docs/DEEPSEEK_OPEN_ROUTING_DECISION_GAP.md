# DeepSeek 开放路由与工程决策能力缺口

## 状态

- 性质：设计问题记录与实验验收依据
- 对应分支：`exp/deepseek-crack-open-discovery`
- 对应草稿 PR：`#17 Experiment: DeepSeek crack open discovery without forced route`
- 相关协议：[DEEPSEEK_CRACK_OPEN_DISCOVERY.md](./DEEPSEEK_CRACK_OPEN_DISCOVERY.md)

## 问题陈述

当前论文案例已经证明：DeepSeek 可以在真实有限元证据、确定性 Skill、运行时校验和求解反馈组成的闭环中选择动作、提交参数、发生错误并根据反馈修正。

但是，这些案例尚不足以证明 DeepSeek 具备开放场景下的工程诊断和路由能力。当前系统会根据 `case_id`、结构化模型类型或预先选择的场景目录提供专用 Skill，并通过 required-artifact 列表规定完成分析必须取得哪些证据。其效果接近：

```text
场景标签或关键词
  → Python 选择专用 Skill 子集
  → Python 规定必需工件
  → DeepSeek 决定调用顺序、参数和表述
```

以裂纹案例为例，如果输入已经标记为裂纹场景，工具目录中只提供裂纹相关分析能力，同时 `elastoplastic_evidence` 又被列为必需工件，那么 DeepSeek 即使给出了合理的塑性区判断，也不能作为“模型自主发现需要弹塑性分析”的干净证据，因为完成合同已经要求它最终取得该工件。

同理，如果系统只需检测用户问题中的“裂纹”字样便进入裂纹专用流程，那么它测试的是规则路由之后的执行能力，而不是对物理问题的识别、竞争假设比较和下一步证据选择能力。

## 核心判断

**固定工程流程不是问题，预先固定工程结论才是问题。**

真实工程师同样依赖规范、SOP、检查表和专业工具。Skill 可以作为工程能力库，确定性运行时也应继续负责 JSON、参数范围、几何合法性、预算和求解器错误等可客观检查的事项。

需要避免的是由 Python 在 DeepSeek 决策前完成以下工作：

- 根据场景标签直接筛选唯一专业路线；
- 把某一物理结论对应的工件列为必需完成条件；
- 将事后评分标准或期望 Skill 名称暴露给模型；
- 因尚未调用某个预定 Skill 而阻止模型结束；
- 把“按照规定顺序执行”表述为“自主发现分析路线”。

## 当前结果能够证明什么

当前受控工作流能够支持以下结论：

- DeepSeek 可以读取真实求解产生的结构化场证据；
- DeepSeek 可以选择 Skill、填写参数并提出非固定坐标的区域；
- DeepSeek 会犯合同错误、证据错配或运行预算错误；
- 确定性校验可以给出可执行的错误反馈；
- DeepSeek 可以在同一会话中根据反馈修正；
- 最终方案可以通过真实重网格、CalculiX 求解和同预算对照验证。

## 当前结果不能单独证明什么

除非增加开放路由实验，否则当前结果不能单独支持以下强主张：

- DeepSeek 能从未分类的用户问题中自主识别裂纹、奇异性、接触或塑性机制；
- DeepSeek 能在统一工具全集中选择正确专业路线；
- DeepSeek 能自主判断是否需要弹塑性分析，而不是完成预设工件；
- DeepSeek 能在多条都合理的工程路线中选择信息价值最高的下一步；
- DeepSeek 的结论不依赖关键词、`case_id`、Skill 名称或提示顺序。

## 目标决策结构

开放路由实验应改为：

```text
原始用户问题 + 未预分类的模型事实 + 当前有限元证据
  → DeepSeek 提出竞争物理假设
  → DeepSeek 从统一 Skill 全集中选择下一项证据
  → 确定性执行层运行并返回真实结果
  → DeepSeek更新判断、补充信息、改变路线或停止
  → 轨迹冻结后再进行独立评分
```

运行时只规定最终输出合同，例如当前判断、证据引用、不确定性、允许用途和禁止用途；不规定必须出现哪些中间 Skill 或物理结论。

## 反事实测试矩阵

开放路由能力不能只通过一个明显带有“裂纹”关键词的案例评价，至少应包含下列反事实对：

| 输入变化 | 期望考察的能力 |
|---|---|
| 用户写“裂纹”，但几何只是有限半径圆角缺口 | 不应仅凭关键词进入断裂力学路线 |
| 用户未写“裂纹”，但 CAD/FEM 拓扑存在裂纹面和尖端 | 应根据物理事实主动发现断裂问题 |
| 相同裂纹几何、低载荷、塑性区相对尺寸很小 | 可以停在线弹性断裂力学，并说明适用边界 |
| 相同裂纹几何、高载荷、塑性区相对尺寸显著 | 应取得材料曲线并考虑弹塑性分析 |
| 存在裂纹但缺少屈服曲线 | 应请求缺失信息或保留结论，不能伪造弹塑性结果 |
| 尖端最大应力持续增加，但固定距离量和 J/G 收敛 | 应停止追逐奇异点值并转换评价量 |
| 应力、能量和 ZZ 误差分别指向不同区域 | 应围绕用户 QoI 解释权重，而不是机械选择最大色块 |
| 相同措辞但模型事实不同 | 应产生不同路线 |
| 不同措辞但模型事实等价 | 应产生一致路线 |

还应执行提示顺序扰动、工具名称盲化、多个随机种子和无关关键词注入，检查模型是否依赖表面线索。

## Skill 与执行层边界

统一 Skill 全集可以保留专业能力说明，但不能把工具的存在变成调用要求。

执行层可以拒绝：

- 无效 JSON；
- 超出 schema 的参数；
- 越界或不可执行的几何；
- 超出显式计算预算的动作；
- 缺少物理前提而无法执行的计算，例如没有裂纹路径却请求 J 积分；
- 求解器失败或结果文件不完整。

执行层不应替 DeepSeek 判断：

- 是否应该采用断裂力学；
- 是否应该从线弹性切换到弹塑性；
- 哪个工程 QoI 最重要；
- 是否值得继续计算；
- 哪条物理解释是最终结论。

当物理前提不足时，Skill 应返回“缺少什么信息以及为何无法执行”，由 DeepSeek 决定补证据、选择替代路线或停止。

## 评价方法

开放决策不能只用“是否调用了期望 Skill”评分。建议同时记录：

- 最终 QoI 误差和安全性；
- 不必要的求解器调用次数和总计算成本；
- Skill 选择的精确率、召回率及无效调用率；
- 是否选择了能够区分竞争假设的证据；
- 最终判断是否与真实证据一致；
- 是否如实表达剩余不确定性；
- 相对专家方案或全搜索参考方案的决策损失；
- 在反事实输入和提示扰动下的一致性。

对照组至少包括固定脚本、人工启发式规则、DeepSeek 开放选 Skill，以及专家或全搜索参考路线。

## 最小验收条件

开放路由实验至少满足以下条件，才能作为 DeepSeek 工程决策能力的证据：

1. 运行时没有场景专用 required-artifact 列表。
2. 模型没有收到预定 Skill 顺序或期望最终结论。
3. 同一统一工具目录服务于全部反事实案例。
4. 模型可以在任意轮次请求信息、选择替代路线或停止。
5. 运行时评分只在轨迹冻结后执行，不参与决策。
6. 至少有一组“出现裂纹关键词但不应进入裂纹路线”的负例。
7. 至少有一组“没有裂纹关键词但应识别裂纹机制”的正例。
8. 至少有一组由载荷或材料事实决定线弹性/弹塑性分支的成对案例。
9. 报告同时保留成功、错误、无效调用、重规划和不确定结论。
10. 论文明确区分受控工作流执行能力与开放工程诊断能力。

## 论文表述边界

在开放路由实验完成前，推荐表述为：

> DeepSeek 作为证据驱动的工程决策策略，在确定性 Skill 约束和真实求解反馈构成的工作流中选择分析行动、模型修正、区域划分与优化参数。

不应表述为：

> DeepSeek 已经能够从任意用户问题中自主发现完整工程分析路线。

如果开放路由反事实实验达到上述验收条件，则可以进一步讨论其在未预分类问题中的诊断、信息获取和专业路线选择能力。
