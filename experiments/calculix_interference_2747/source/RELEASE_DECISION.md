# 原始大型输入发布决策记录

记录日期：2026-07-31。

## 决策目标

用户要求同时交付缩减模型证据和论坛作者提供的原始大型 `.inp`，并要求保留可审计的决策路径。

## 已核实输入

1. 作者公开的 `Shear_setups.zip` 已取回并通过 SHA-1、SHA-256 与归档内容复核。
2. 归档恰好包含两个自包含 `.inp`，大小分别为 267,223,015 和 277,391,649 字节。
3. 两个输入均超过 GitHub 普通 Git 的 100 MiB 单文件限制。
4. 原始归档没有明确许可证。
5. 当前原模型根因仍为 `narrowed_unresolved`，且本仓库未执行约 1160 万自由度、请求 Pardiso 的原始大型模型。

## 决策

1. **大文件位置：GitHub Release。** 原始 ZIP 和两个解压后的 `.inp` 作为 Release assets；普通 Git 只保存清单、哈希、来源与边界。
2. **发布类型：prerelease。** 这表示证据已冻结并可下载，不表示论坛问题已经解决。
3. **保真方式：原字节。** ZIP 不重打包，两个 `.inp` 直接取自原归档，不修改换行、关键字或数值。
4. **下载便利性：ZIP 与裸 `.inp` 同时提供。** ZIP 保留作者原始发布单元，裸 `.inp` 让高级用户可直接下载其中任一大型模型。
5. **许可表达：不代授许可。** Release 明示第三方来源、无明确许可证和移除渠道，不把仓库许可证扩展到原模型。
6. **结论边界：原模型未求解。** Release 同时附上缩减模型反事实 PDF，但明确它不是大型模型求解结果。
7. **其他研究问题：进入可审查的案例分支。** 相场断裂、经典案例迁移和多个既有方法组合均是小型文本问题定义，应放在 deployment case library 的 PR #20，而不是混入本接触问题的大文件 Release。

## 被否决的替代方案

- **直接提交到 Git：** 被 100 MiB 单文件硬限制否决，也会永久膨胀历史。
- **为本附件启用 Git LFS：** 技术上可行，但会为整个仓库引入配额和 clone 语义变化；对一次性第三方研究包收益不足。
- **只保留 Proton 外链：** 无法防止外链变化，也不满足用户要求的原始输入交付。
- **把缩减模型当作原模型：** 会混淆证据层级，违反当前求解事实。
- **标为正式稳定 Release：** 根因和原始大型求解尚未闭合，不符合证据状态。
